# Contributing

Changes should describe the concrete behavior implemented and the tests run.
Keep completed behavior and unsupported cases clear in review descriptions.

- Submit only code or data you have the right to contribute.
- Project-owned changes use MPL-2.0; preserve existing author and license notices.
- Keep upstream dependency notices, versions and local patch records intact.
- Use small synthetic inputs for tests whenever possible.
- Keep game content, user saves, captures, binaries and package caches outside Git.
- Run `python scripts/check_public_tree.py` before publishing changes.

Compatibility work should record the supported input format and explicit limits.
Do not add proprietary source or captures to demonstrate a behavior.
